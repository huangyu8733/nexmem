# 推送凭证接入指南（面向二次开发者）

Nexmem 的推送链路已经写好，**凭证不内置在代码或安装包里**。本 App 默认可以编译、启动、正常使用；
未配置凭证时设置页显示「当前平台不支持 / 尚未获取设备令牌」，不影响消息收发。
接入方按下面步骤填入自己的凭证即可启用系统级通知。

---

## 1. 整体链路

```
宿主 App 获取设备令牌（FCM / APNs / Web Push）
  → PushPlatform.getToken()
  → PushController 调内核 push.register（带 apns:/fcm:/web: 前缀）
  → 内核签名后 POST /v1/push/token 落到索引服务 push_tokens
  → 离线投递时索引服务 POST /v1/push/wake
  → Router 按前缀分发 APNs / FCM / Web Push
  → 设备被唤醒，自行走离线通道拉密文（推送本身不含正文）
```

推送载荷只有 `{has_offline: true, acct: ...}` 或 Web 空载荷；
**不携带消息正文、发送者、会话标题**，符合隐私设计。

---

## 2. Android（FCM）

### 2.1 凭证

在 Firebase 控制台创建项目和应用（包名 `io.nexmem.nexmemApp`），下载 `google-services.json`。

### 2.2 宿主侧实现

在 `app/android/app` 中接入 `firebase-messaging`，实现 `MethodChannel('nexmem/push')`：

| 方法 | 返回 | 说明 |
|---|---|---|
| `permission` | `String` | `granted` / `denied` / `prompt` |
| `requestPermission` | `String` | Android 13+ 请求 `POST_NOTIFICATIONS` |
| `getToken` | `Map?` | `{token, platform: 'fcm', env: 'production'}` |
| `show` | `void` | 参数 `{title, body, conversationId}`，发通知栏 |
| `clear` | `void` | 参数 `{conversationId}`，移除对应通知 |

并通过 `EventChannel('nexmem/push/events')` 推送：

- `{"type":"token","token":"...","platform":"fcm","env":"production"}`（令牌刷新）
- `{"type":"open","conversationId":"dm:..."}`（用户点击通知）

收到 FCM data 消息（`has_offline=1`）时不要展示正文，只发本地「有新消息」通知。

### 2.3 服务端

索引服务启动时设置：

```bash
NEXMEM_FCM_ACCOUNT=/path/to/service-account.json
```

`service-account.json` 需要 `project_id` / `client_email` / `private_key` 三个字段。
`push.Config` 的 `WakePerAccountPerSecond` 限制唤醒频率。

## 3. iOS（APNs）

### 3.1 凭证

Apple Developer 生成 **Auth Key（.p8，APNs）**，记录 Key ID 与 Team ID；
Xcode 打开 Push Notifications capability，确认 Bundle ID 与 apns-topic 一致。

### 3.2 宿主侧实现

同样实现 `nexmem/push` 通道；`getToken` 返回原生 APNs device token：

```json
{"token": "<hex device token>", "platform": "apns", "env": "production"}
```

注册 `UNUserNotificationCenterDelegate`，收到后台静默推送后触发本地通知；
点击通知时经 EventChannel 发 `{"type":"open","conversationId":"..."}`。

### 3.3 服务端

```bash
NEXMEM_APNS_KEY=/path/to/AuthKey_XXXXXXXXXX.p8
NEXMEM_APNS_KEY_ID=XXXXXXXXXX
NEXMEM_APNS_TEAM_ID=YYYYYYYYYY
NEXMEM_APNS_BUNDLE_ID=io.nexmem.nexmemApp
# 开发/沙箱环境：
NEXMEM_APNS_SANDBOX=1
```

## 4. Web 通知

### 4.1 浏览器通知（无需凭证，默认可用）

用户开启「消息通知」后，浏览器请求 `Notification` 权限；页面打开时收到消息会显示本地通知。
`app/web/sw.js` 已随构建产物发布，负责点击回传 `conversationId`，Flutter 侧自动打开会话。

### 4.2 后台唤醒（需 VAPID 公钥）

部署者生成一对 VAPID 密钥（P-256），公钥有两种注入方式（二选一）：

1. **应用内填写（推荐）**：打开「设置 → 开发者 → Web Push VAPID 公钥」填入 base64url 公钥并保存。公钥写在本机设置 `developer.vapid_public_key`，不需要重新构建；更换公钥后会自动退订旧订阅并重新订阅。
2. **构建期注入**：仍兼容原有方式：

```bash
flutter build web --dart-define=NEXMEM_WEB_VAPID_PUBLIC_KEY=<base64url 公钥>
```

应用内填写的值优先于构建期值；清空后恢复构建期值。

服务端配置私钥与 subject：

```bash
NEXMEM_VAPID_KEY=/path/to/vapid-private.pem
NEXMEM_VAPID_SUBJECT=mailto:admin@example.com
```

未注入公钥时 App 只启用浏览器本地通知，不请求 PushManager 订阅，功能不报错。
注意 Web Push 需要 HTTPS（localhost 除外）。

> 「设置 → 开发者」提供两种凭证填写：地图 Key 与 VAPID 公钥会写进本机 KV；
> APNs / FCM / VAPID **私钥**只在该页内存中用于生成环境变量配置文本，
> 不落盘、不上传、不随消息发送。服务端私钥请不要填进客户端设置。

---

## 5. 桌面端

macOS / Windows / Linux 没有系统通知通道，设置页显示「当前平台不支持」。
应用保持打开时仍会有右上角提示 + 叮咚声，消息不丢失。

---

## 6. 验证清单

- [ ] 未配置任何凭证时 App 能编译、启动、收发消息，设置页无红屏。
- [ ] Android 授权后 `getToken` 返回非空，内核 `push.register` 成功。
- [ ] iOS 真机收到静默推送后唤醒，点击通知打开对应会话。
- [ ] Web 页面授权后显示浏览器通知，点击跳转到对应会话。
- [ ] 凭证错误时只影响推送，不影响主流程；已登记令牌不会被误删。
- [ ] 服务端 `curl /v1/push/wake?account=...` 返回 `enabled=true` 且 `sent>0`。
